# 改造方案：从页面级拦截重构成「进入 App 全局应用锁」

## 需求与设计变更
用户反馈：原先进入「设置」与「虚拟屏」的分页面拦截会导致切页手势、横竖屏旋转与导航状态互相耦合且容易出现体验 Bug。现改为**进入 App（冷启动或从后台切回）时进行全局系统锁身份验证**。

### 核心特性
1. **全局应用锁门禁 (`AppLockGate`)**：
   - 当应用冷启动进入、或从后台（Home 键切出、锁屏熄屏）重新切回前台时，显示全屏应用锁界面。
   - 自动拉起 Android 原生锁（BiometricPrompt：支持指纹/面部识别与系统 PIN 码/图案/密码回退）。
   - 验证通过后解锁整个应用，进入后所有页面（主页、AzurPilot、设置、虚拟屏）均可自由流畅切换，无任何页面级拦截干扰。
2. **免密规则**：
   - 依旧遵循 `KeyguardManager.isDeviceSecure` 检测：若设备未设置系统锁屏密码，自动免密放行，无感知直接进入 App。
3. **退后台重锁**：
   - 监听 Activity 生命周期 `Lifecycle.Event.ON_STOP`（应用不可见时），将解锁状态置为锁定；当应用再次 `ON_START` 返回前台时触发应用锁。
   - 注意：Android `BiometricPrompt` 弹窗仅使 Activity 进入 `onPause`，不会触发 `onStop`，因此锁屏在生命周期上稳定可靠。
4. **清理原有页面级复杂逻辑**：
   - 还原 `AppRoot.kt` 中的底栏 `NavigationBarItem` 与侧栏 `NavigationRailItem` 为直接点击导航。
   - 还原 `HorizontalPager` 的 `userScrollEnabled` 行为。
   - 移除 `ScreenPage` 与 `SettingsScreen` 内部的页面级包裹，彻底消除切页卡顿与旋转时的交互 Bug。
5. **设置项适配**：
   - 设置项更新为「应用锁屏保护」（默认开启），支持在关闭时验证身份，未设锁屏时提示免密。

## 改造步骤清单

1. **认证与状态管理重构 (`AppLockManager.kt`)**：
   - 重命名/重构为 `AppLockManager`（单例）：
     - 维护全局 `isUnlocked: MutableStateFlow<Boolean>` 状态。
     - `isLockRequired(context)`：当且仅当 `appSettings.appLockEnabled && keyguardManager.isDeviceSecure`。
     - `authenticate(activity, onSuccess, onCancel, onError)`：调起原生指纹/面部/PIN 码验证。
     - `lock()`：锁定状态。
   - 在 `CoreModule.kt` 中注入 `AppLockManager`。

2. **全局应用锁组件 (`AppLockGate.kt`)**：
   - 在 `AppRoot` 最外层覆盖展示：
     - 展示应用图标、应用锁提示文案、解锁按钮。
     - 刚进入或返回前台时自动尝试调起一次系统原生锁验证；若用户主动取消，保留在锁屏界面并提供「点击解锁」按钮。

3. **还原 `AppRoot.kt` 页面交互与接入全局门禁**：
   - 监听 `ON_STOP` 生命周期调用 `appLockManager.lock()`。
   - 恢复导航栏与侧栏的直接 `goToPage(index)` 点击。
   - 恢复 `HorizontalPager` 各页面直接渲染，去除所有二级/页面级的 `SensitiveAuthGate`。
   - 在最外层根据 `appLockManager.isUnlocked` 呈现 `AppLockGate` 遮罩。

4. **更新设置与配置存储**：
   - `AppSettings.kt`：`appLockEnabled: String = "true"`。
   - `AppSettingsManager.kt` / `AppSettingsGateway.kt` / `FakeAppSettingsGateway.kt`：同步更新接口。
   - `SettingsContracts.kt` / `SettingsViewModel.kt`：`appLockEnabled` 与 `SetAppLock` 意图。
   - `SettingsScreen.kt`：更新开关标题为「应用锁屏保护」，关闭时前置身份验证。

5. **多语言与文案更新 (`strings.xml`)**：
   - 同步更新 4 份语言文件（`values/`、`values-en/`、`values-ja/`、`values-zh-rTW/`），确保键名对齐。

6. **编译验证**：
   - 运行 `./gradlew :app:compileDebugKotlin -Pazurpilot.slimApk=true` 及多语言对齐检查脚本。
