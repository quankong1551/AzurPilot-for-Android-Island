# 开源许可证完整展示与协议原文查看实现计划

## 1. 现状与问题分析
- 当前设置中的“关于”页（`AboutSettingsPage`）仅硬编码了 7 个组件，且点击后调用系统浏览器直接跳转到外部 GitHub 页面，无法在应用内查看许可证协议正文。
- 列表中提供了一个“查看完整 Android 依赖清单”的入口，但也是直接外链至 `libs.versions.toml`，未在应用内完整呈现所有实际运行时的开源组件及传递依赖。
- 此外，项目还内嵌并使用了 PRoot 原生九件套（Busybox、libtalloc、pcre2 等）、upstream AzurPilot、scrcpy 移植代码等非 Maven 开源组件，当前界面均未完整收录其开源协议原文。

## 2. 方案目标
1. **收录所有开源组件**：
   - **核心与内置组件**：AzurPilot (GPL-3.0), PRoot (GPL-2.0), BusyBox (GPL-2.0), libtalloc (LGPL-3.0), PCRE2 (BSD-3-Clause), libandroid-shmem (Apache-2.0), libandroid-selinux (Apache-2.0), scrcpy 移植组件 (Apache-2.0), ALAS-AOS 基础项目 (AGPL-3.0) 等。
   - **Android 运行时所有第三方开源依赖项**：包括直接与关键传递依赖（Kotlin Stdlib/Coroutines/Serialization, Jetpack Compose 家族, AndroidX 核心与 UI 家族, OkHttp, Koin, Timber, Commons-compress, XZ, FloatingX, Shizuku, Libsu, XXPermissions 等全部开源运行构件）。
2. **点击可查看完整的协议原文**：
   - 点击任意开源组件条目，进入该组件的专属“协议详情”二级页面。
   - 显示组件完整名称、组织/构件 ID（`group:artifact`）、版本号、开源协议类型（SPDX 标识）、项目官方仓库链接（可外跳）。
   - 完整展示该组件适用的**开源许可证法律协议原文正文（License Text）**，支持滚动阅读、长按选择与一键复制协议文本。
3. **离线高可靠与零构建风险**：
   - 许可证正文与组件元数据收录于本地 JSON 资产库中，共享标准 SPDX 协议文本（Apache-2.0, GPL-2.0, GPL-3.0, AGPL-3.0, LGPL-3.0, BSD-3-Clause, MIT, 0BSD/Public Domain 等），保证 100% 离线可用、无远程拉取失败风险、且不引入第三方 Gradle 插件对 AGP 9 / Gradle 9 的兼容性隐患。
   - 配套提供 Python 校验脚本，确保后续在 `libs.versions.toml` 变更依赖时可自动校验覆盖率。

---

## 3. 具体实施步骤

### 步骤 1：构建离线开源组件与许可证资产库
- 在 `app/app/src/main/assets/licenses/licenses.json` 建立结构化数据：
  - `licenses`: 包含标准开源协议的完整法定英文原文（Apache-2.0, MIT, GPL-3.0, GPL-2.0, LGPL-3.0, AGPL-3.0, BSD-3-Clause, Public-Domain/0BSD 等）。
  - `components`: 包含所有开源组件详细信息，字段包含 `id`, `name`, `group`, `artifact`, `version`, `licenseId`, `url`, `description`, `category` (core / android_lib)。
- 编写校验脚本 `app/scripts/check_licenses.py`，用于自动化核对 `libs.versions.toml` 与 `licenses.json` 的匹配性。

### 步骤 2：建立数据层模型与 Repository
- 新建 `com.azurpilot.ghio.domain.license` 包：
  - 数据模型：`OpenSourceComponent`、`OpenSourceLicense`、`LicenseCatalog`。
  - 仓储接口与实现：`LicenseRepository`，利用 `Context.assets` 读取解析 JSON，提供：
    - 获取全部开源组件列表
    - 按分类（核心组件 / Android 运行库）与关键词实时检索
    - 根据组件 ID 或许可证 ID 获取协议详情及完整正文
- 在 Koin 依赖注入配置（`app/app/src/main/java/com/azurpilot/ghio/di/AppModule.kt`）中注册单例 `LicenseRepository`。

### 步骤 3：实现 UI 界面与路由交互
- 扩展 `SettingsScreen.kt` 中现有的 `SettingsSubPage` 组件为 internal，支持动态标题字符串。
- 在 `Routes.kt` 中注册二级路由：
  - `Routes.SETTINGS_LICENSES = "settings/licenses"`（全部开源组件列表）
  - `Routes.SETTINGS_LICENSE_DETAIL = "settings/licenses/{id}"`（单个组件协议详情及原文）
- 新建界面组件：
  - `OpenSourceLicensesPage`：
    - 顶部支持按组件名、组织、许可证（如 Apache, GPL）实时过滤的搜索框；
    - 分类呈现“核心与内置组件”与“Android 运行依赖”；
    - 每一项展示名称、版本、组织和许可证 Badge，点击平滑推入协议详情页。
  - `LicenseDetailPage`：
    - 顶部组件元数据卡片（全称、版本、SPDX 协议名、访问官方项目外跳按钮）；
    - 协议正文阅读卡片（完整排版协议原文、代码/等宽易读样式、顶部提供一键复制全文操作及 Snackbar 反馈）。
- 改造现有的 `AboutSettingsPage`：
  - 替换原来的手工 7 项列表与外跳链接；
  - 放置“开源组件与许可证”入口（动态展示收录的总组件数量，点击进入完整列表）；
  - 保留 AzurPilot、PRoot、Shizuku 等核心组件的快捷条目，点击直接直达该组件的协议原文详情页。
- 在 `AppRoot.kt` 的 `NavHost` 中注册 `SETTINGS_LICENSES` 与 `SETTINGS_LICENSE_DETAIL` 路由目的地。

### 步骤 4：多语言支持与合规校验
- 在 `values/strings.xml`（中文基准）、`values-en/strings.xml`、`values-ja/strings.xml`、`values-zh-rTW/strings.xml` 中配置新增多语言文案（开源组件、协议原文、搜索组件、复制成功、访问项目主页等）。
- 运行 `python app/scripts/check_i18n_strings.py` 确保多语言一致性。

### 步骤 5：编译与回归验证
- 运行 `compileDebugKotlin -x verifyBundledAzurPilotRuntime` 验证 Kotlin 编译通过。
- 运行 `python app/scripts/check_licenses.py` 验证依赖收录完整性。
