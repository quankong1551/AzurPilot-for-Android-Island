## Runtime 自动更新实现方案（修订版）

### 核心设计变更

调度器的安全停止和复活由 **上游运行时** 自己管理，不由 App 侧越权操作：

1. App 调 `POST /android/update/suspend` → 运行时写 `config/reloadalas` + 优雅停实例
2. App 停 proot → 换 rootfs → 起 proot
3. 运行时启动时读 `config/reloadalas` → 自动复活实例（已有逻辑）

### 改动清单

#### 上游 AzurPilot（Python，1 个文件改动）

**`module/api/android.py`** — 新增 `/android/update/suspend`

在 `dispatch()` 的 update 路由区添加分支，在 `routes()` 返回列表末尾添加 Route：

```python
if path.endswith('/update/suspend') and request.method == 'POST':
    return JSONResponse(await asyncio.to_thread(_suspend_for_update))
```

`_suspend_for_update()` 实现（闭包，定义在 `routes()` 内部）：

```python
def _suspend_for_update():
    """为整包更新挂起所有运行实例。

    枚举运行中的调度器和工具任务，写 config/reloadalas 恢复清单后
    逐个优雅停止。下次 WebUI 启动时 restart_processes() 读取该清单
    自动复活被挂起的实例。
    """
    with _operation_lock:
        instances = ProcessManager.running_instances()
        names = [alas.config_name for alas in instances]
        # 工具任务也记录
        tool_config, _ = active_tool()
        if tool_config and tool_config not in names:
            names.append(tool_config)
        if names:
            atomic_write('./config/reloadalas',
                         ''.join(n + '\n' for n in names))
        for alas in instances:
            alas.stop()
        return {'ok': True, 'suspended': names}
```

需要在文件顶部 import `atomic_write`（`from deploy.atomic import atomic_write`）。

#### App 侧（Kotlin，5 个文件修改 + 1 个新文件）

##### 1. 新建 `RuntimeAutoUpdater.kt`（`provision/` 包）

自动更新编排器，Koin 单例。

**依赖：** `Application, CoroutineScope, AppSettingsManager, RootfsProvisioner, ProotHost, AzurPilotRunController`

**状态机（sealed interface `AutoUpdateState`）：**
```
Idle → Checking → Downloading(done, total) → Extracting(done, total)
     → Suspending → Swapping → Verifying
     → Completed(version)  或  RollingBack → Failed(reason, rolledBack)
```

**核心流程：**
1. `start()` 幂等启动 30 分钟一次的周期循环
2. 每个 tick 前置条件：`hotUpdateEnabled` 打开、当前 Idle、调度器和工具空闲
3. `Checking`：调 provisioner 的 `fetchIndex()` + `parseRuntime()`，只在非 `commitOnly` 的全量更新时继续（`commitOnly` 留给运行时内热更）
4. `Downloading`：用 `ReleaseDownloader` 下载 `rootfs-<abi>.tar.xz`，支持镜像切换、进度回调
5. SHA-256 校验
6. `Extracting`：调 provisioner 的 `extractToStaging()` 解压到 `rootfs.tmp`（自动迁移 config/log/**reloadalas**）
7. **`Suspending`：`POST /android/update/suspend`** — 运行时写 `reloadalas`、优雅停所有实例；若接口不可达（运行时未跑）则跳过
8. `Swapping`：`prootHost.stopAndAwait()`，调 provisioner 的 `commitStaging()` 原子换名
9. `Verifying`：`prootHost.ensureStarted()` + HTTP 探活（`/android/status` + `/healthz`，90s 上限）
10. 健康通过 → `cleanupPrevious()` → `Completed(version)`
    - 运行时自己的 `restart_processes()` 读 `reloadalas` 自动复活被挂起的实例
11. 健康失败 → `RollingBack` → `prootHost.stopAndAwait()` → `rollbackStaging()` → `prootHost.ensureStarted()` → `Failed(reason, rolledBack=true)`

暴露 `val busy: StateFlow<Boolean>` 给 `AzurPilotRunController` 做互斥。

##### 2. 修改 `RootfsProvisioner.kt` — 拆分 extract 为 prepare + commit

将原 `extract()` 拆为两阶段：

- **`internal fun extractToStaging(openArchive, total, expectedVersion)`**
  tar 解压到 `rootfs.tmp` + 校验清单/Python + 写 marker + 从当前 rootfs 迁移用户 config/log
  
- **`internal fun commitStaging()`**
  原子换名：`rootfs` → `rootfs.previous`，`rootfs.tmp` → `rootfs`

- **`internal fun rollbackStaging()`**
  回滚：删损坏的 `rootfs`，`rootfs.previous` → `rootfs`

- **`internal fun cleanupPrevious()`**
  删 `rootfs.previous`

- 将 `fetchIndex()`、`parseRuntime()`、`ReleaseRuntime` 数据类、`downloadArchive()` 改为 `internal`

- 原有 `extract()` 改为顺序调两阶段，行为不变

- **config 迁移扩展**：除现有的 `.json` 文件外，额外复制 `config/reloadalas`（如果存在）。这保证 suspend 写的恢复清单能随 rootfs 切换迁移到新目录。

##### 3. 修改 `ProotHost.kt` — 添加 `stopAndAwait()`

新增 suspend 函数，供 `RuntimeAutoUpdater` 在 swap 前调用：
- 设 `wantRunning = false`
- 取消 `supervisorJob`（防止退避重拉）
- 在 `startMutex` 内：关 stdin → 等进程退出 → destroyForcibly 兜底
- 返回时 phase 已为 IDLE

原有 fire-and-forget `stop()` 不动。

##### 4. 修改 `AppRoot.kt` — `hotUpdateEnabled` 全覆盖

```kotlin
// 旧：仅 commitOnly 走热更，非 commitOnly 仍弹对话框
val fullUpdatePending = runtimeAvailable && !(runtimeCheck.commitOnly && hotUpdateOn)

// 新：热更开关打开时一律不弹，全量更新交给 RuntimeAutoUpdater 后台处理
val fullUpdatePending = runtimeAvailable && !hotUpdateOn
```

关闭开关 = 恢复手动对话框（逃生门不变）。

##### 5. 修改 `AzurPilotRunController.kt` — 与自动更新互斥

- 构造器增加 `autoUpdateBusy: StateFlow<Boolean> = MutableStateFlow(false)` 参数
- `hotUpdateTick()` 开头加 `if (autoUpdateBusy.value) return` — 全量更新进行中不跑源码热更

##### 6. DI 模块

**`ProvisionModule.kt`：**
```kotlin
single { RuntimeAutoUpdater(
    androidApplication(), get(named<AppCoroutineScope>()),
    get(), get(), get(), get()
) }
```

**`ProotModule.kt`：**
```kotlin
single {
    val autoUpdater = get<RuntimeAutoUpdater>()
    AzurPilotRunController(
        androidApplication(), get(named<AppCoroutineScope>()), get(), get(),
        autoUpdateBusy = autoUpdater.busy,
    )
}
```

启动挂载：在 `AzurPilotRunController.start()` 旁加 `autoUpdater.start()`。

### 调度器自动重启的完整链路

```
App: POST /android/update/suspend
  └→ 运行时: 枚举运行实例 → write config/reloadalas → 优雅停止 → 返回 {ok, suspended}
App: prootHost.stopAndAwait()
App: commitStaging()  (rootfs → rootfs.previous, rootfs.tmp → rootfs)
  └→ config/reloadalas 随 config/ 迁移到新 rootfs
App: prootHost.ensureStarted()
  └→ 运行时 WebUI 启动 → lifecycle.startup()
    └→ ProcessManager.restart_processes() 读 config/reloadalas → 自动复活实例 → 删 reloadalas
```

### 关键设计

| 决策 | 选择 | 理由 |
|---|---|---|
| 实例挂起/复活 | 运行时侧 API，复用 reloadalas 机制 | 运行时自己管理进程生命周期最安全 |
| 自动更新时机 | 调度器/工具空闲时自动触发 | 不打断运行中的游戏任务 |
| 回滚 | 90s 健康检查失败 → rootfs.previous 换回 | 最小可用保证 |
| 控制开关 | 复用 `hotUpdateEnabled` | 统一"自动更新"意图；关闭即恢复手动对话框 |
| 与热更互斥 | `autoUpdateBusy` StateFlow | 全量更新进行中跑热更无意义 |
| config 迁移 | 扩展过滤器包含 `reloadalas` | 保证恢复清单跟随 rootfs 切换 |
